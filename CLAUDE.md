# CLAUDE.md - Codarr

`plan.md` is the specification. It is the source of truth for every behavioural
question, and its section 26 checklist is the thing to re-read before claiming a
piece of work is done. This file covers how the repo is built, not what it does.

## Tech stack

- **Language**: Go 1.27+, one binary, CGO off
- **HTTP**: `go-chi/v5`, handlers generated from `api/openapi.yaml` by `oapi-codegen`
- **DB**: SQLite via `modernc.org/sqlite` (pure Go), migrations via `rubenv/sql-migrate`
- **Logging**: `log/slog`, JSON to stdout, with a secondary sink into the `events` table
- **Mocks**: `matryer/moq`
- **Frontend**: Vite + React 19 + TypeScript + Tailwind v4, embedded via `go:embed`
- **Linting**: golangci-lint v2, strict config in `.golangci.yaml`

## Project structure

```
api/            OpenAPI spec plus generated models and server. Not hand-edited.
cmd/codarr/     The only binary. Wiring, no business logic.
data/           embed.go plus migrations/. 001_schema.sql is never edited.
internal/
  api/          StrictServerInterface implementation, hand-written
  arr/          Radarr and Sonarr clients, one per instance
  decide/       Decision engine and the hard-coded policy
  ffmpeg/       argv builder, runner, progress parser
  ffprobe/      Probe wrapper and its JSON model
  hardware/     QSV and VAAPI capability probe
  ingest/       Webhooks and the scheduled scan
  job/          Queue, worker, state machine, crash recovery
  plex/         Sessions, libraries, refresh, analyze, PIN auth
  promote/      Preflight, staging, verification, atomic rename
  web/          go:embed of the built SPA plus the fallback handler
  pkg/          Shared: domain, store, fsx, clock, pathmap, fingerprint, events, metrics
web/            Vite project. Builds INTO internal/web/dist.
```

Shared code lives under `internal/pkg/`. There is no root `pkg/`.

## Commands

```bash
make ci            # fumpt, generate, lint, vet, govulncheck, go test ./...
make cover         # coverage for decide and ffmpeg, which must stay near 100%
make build         # builds the frontend, then the binary with it embedded
make run           # run against CODARR_DB (default ./data/codarr.db)
make web-dev       # Vite dev server, proxies /api to the Go server
make image         # amd64 image. QSV and the Intel driver are amd64 only
```

**Always run `make ci` after each work step and fix everything it reports
before moving on.**

## Non-negotiables

These come straight out of `plan.md` and a change that violates one is a bug,
not a preference.

- **Encoding policy is hard-coded.** No setting changes what gets transcoded or
  to what. Policy lives in Go constants in `internal/decide` and is displayed
  read-only.
- **Promotion is irreversible.** There is no trash, no undo, no restore. The
  verification in `internal/promote` is the only thing between a bad encode and
  a destroyed source. Never add a force-promote escape hatch.
- **Never skip a file on the CODARR tag alone.** The skip rule is a conjunction:
  tag present AND policy hash matches AND the current fingerprint equals the
  recorded output fingerprint. A third-party rewrite that preserves global tags
  is the realistic case this exists for.
- **Exactly one transcode at a time**, one worker goroutine consuming the queue.
- **Never replace a file Plex is currently streaming.** Defer, do not skip. On
  NFS this produces ESTALE for the reader, not graceful continuation.
- **Index codec, disposition and bitstream-filter options by OUTPUT stream
  position, never source position.** This is the single most valuable thing to
  cover with golden-file tests.
- **No auth layer.** Access is secured externally by the cluster's SSO.
- **No SSE, no WebSocket.** The UI polls every 10 seconds.

## Code style

Follows `bolan-api`.

- Constructors take dependencies; packages never instantiate their own.
  Everything is wired in `cmd/codarr/main.go`.
- Compile-time interface checks: `var _ Prober = &prober{}`.
- Errors wrapped with `%w`. Sentinel errors per package.
- Interfaces are small and defined by the consumer. `Prober` has one method.

### Comments

Default to zero. Code is the documentation.

Write one only when the WHY is not derivable: a workaround, a non-obvious
constraint, a deliberate deviation, a pointer at the `plan.md` section that
explains it. Never restate what a line does. Go doc comments on exported
identifiers only, one sentence, starting with the identifier name.

`plan.md` is full of "the obvious implementation is wrong here" reasoning. Where
a piece of code exists because of one of those, cite the section number rather
than reproducing the argument.

## Tests

- `testify/require` only, never `assert`.
- `t.Parallel()` in every test.
- `TestSubject_Behaviour` naming.
- Assert full structs, not counts.
- Mocks generated by moq into a `mock/` subpackage next to the interface.
- Golden files in `testdata/` beside the package.
- ffmpeg-dependent integration tests skip when ffmpeg is absent.

`internal/decide` and `internal/ffmpeg` carry a near-100% branch coverage
target. Everything else is best effort.

## Don'ts

- Don't make encoding policy configurable.
- Don't add a trash, undo or restore path.
- Don't collapse `audio_only` into `full`.
- Don't compare `pix_fmt` as a string to test chroma; test subsampling.
- Don't treat unknown or absent `field_order` as interlaced.
- Don't pass `-hwaccel` for a codec outside the hardware-decode set.
- Don't put `-pix_fmt` on a hardware-surface pipeline, or `bwdif` on a
  hardware-decode one.
- Don't log or return secrets. GET returns a mask; PUT only overwrites when the
  value is not the mask.
- Don't hand-edit anything under `api/*.gen.go` or `web/src/api/schema.d.ts`.
- Don't commit `.env`.
